# Council skill — protocol history

The compatibility marker lives in `SKILL.md` (`council-protocol: vN`). This file records what each version changed; it is documentation only and is never loaded by the council.

## v11 (2026-09-10)

Restructured after the sixth Codex review (rating 6/10, fourteen findings): the skill is now twelve numbered sections with ONE authoritative state table (state, the artifact that must exist before it is written, the expected document hash, the resume action); Hard rule 5 is "artifact first, then status; intent first, then action"; new intent states `dispatching` (a `DISPATCH INTENT` line and an attempt number before any launch, and a job-listing audit that adopts or re-launches an unreceipted job), `ABANDONING` and `HANDING OFF (relay)` (the user's decision is durable before cleanup starts); an expected-hash rule per state replaces the "newest hash" wording; alternative fixes live under the original concern ID (`R1-G-3/a`) instead of nested remedy points, so accepting any alternative settles the concern; one edit schema (op / anchor / text / marker) for round edits and final-review resolutions, with an application-conflict outcome for each (round: back to carried; final review: the verdict is voided and re-asked); the Claude-only fallback rewrites the round roster (`SEATS (round N)`) and the `claude-2` seat has a name, an ID letter and a critique file; `ROUND TARGET` makes the fixed-rounds count explicit and a reopen raises it; the relay handoff converts fix-pending concerns into a `handoff-ledger.md` the relay core can read; `CHECKPOINTS:` is decided before LOG.md exists (an adapter asks about repository initialisation first); a pre-LOG.md pause belongs to the adapter alone; the document-identity check runs before caller routing and the named file is passed along; the close-out check is a named procedure adapters run too; the pitfalls table keeps only what no section covers. Prose is wrapped at 76 columns. The plangenie adapter's Step 2 was cut to the true overrides.

## v10 (2026-09-10)

Answered the fifth Codex review (rating 5/10, fourteen findings): resumption is logged and `PAUSED` normalised BEFORE the continuation runs, never after; `DOC AT DISPATCH (round N)` is logged with every dispatch and an external change to the document (a hash that matches no logged stage and an edit whose anchor is gone) is never "repaired" — it is a user question or a point sent back to the final review; single-seat and Claude-only rounds are durable state (`SEATS (round N):` and `WAIVED (round N):` lines) and `collected` means every non-waived seat; `AGREE WITH CHANGE` gives the parent point the state `concern agreed (fix pending)` with defined transitions when a remedy is accepted, rebutted, or left at the round limit; final-review markers carry the item number `i` everywhere (`k` is only the STATUS counter); the final review's AFTER hash and `resolved` are one write made after FINAL.md's ledger is rewritten, and an AFTER-hash match on resume skips document writes only; a zero-item final review goes straight to `resolved` in one write; LOG.md records `CALLER:` (standalone or the adapter and its resume command) and a bare `/council resume` of an adapter's council continues through the adapter; the `HANDED OFF:` line records the next seat and the adapter rebuilds its relay state from it if the stop hit between the two writes; every packet ends with `END COUNCIL REVIEW PACKET` (the same terminator PLANGENIE.md relay mode uses, so a handoff needs no conversion); checkpoint commits stage only paths that exist, and `CHECKPOINTS: git | files-only` is recorded at Setup; `CLOSED` is written after the hand-off notes and a `CLOSED` LOG.md whose closing commit is missing gets that commit on the next invocation; round-1 critiques are numbered. The revision history moved to this file.

## v9 and earlier

2026-09-07; v9 answered the fourth Codex review of 2026-09-07: the pause step lands at `collected` only when both critiques are on disk; a `HANDED OFF (relay, …)` status and a "Handing a council to relay mode" section make the adapter's relay fallback a written transition (jobs cancelled, pins restored, debate files kept live); a tally rule for a reopened point that sits with both seats at once; the final-review counter `k` is a count, distinct from the item number `i`; a critique file counts as saved on resume only if it ends with `END OF CRITIQUE`; the reopen ledger is committed; the Copilot council refuses to continue a Claude Code council that still has live jobs or pins.

v8 answered the third Codex review of 2026-09-07: the write that sets `FINAL REVIEW (m/m)` also logs the final review's `DOC BEFORE APPLY` hash, and every hash line names its stage (`round N` / `final review c`) so reconciliation only ever compares against the current stage's own pair; a marker walk checks the edit's content as well as its marker; final-review item numbers continue across cycles; "run more rounds" is a defined reopen transition (a post-verdict ledger file, `LEDGER:` re-pointed, frozen items the user left open become carried again, round numbering continues); a new "Abandoning a council" section that cancels jobs and restores the agent pins before anything is archived; LOG.md records the planning directory and the job root as two absolute paths and the pause receipt names the planning directory; a packet is reused on resume only when it ends with `END OF PACKET`, every critique must end with `END OF CRITIQUE`, and a reply reporting a truncated packet is a seat failure, never a clean review; a council-agreed edit that changes or contradicts a line the document marks as the user's own is never applied automatically — it is a `user decision` point that reaches the final review.

v7 answered the second Codex review of 2026-09-07: LOG.md carries a `LEDGER:` line naming the newest merge file and every resume loads it, so a stop early in round N still has round N-1's frozen points; council-verified edits carry their point IDs too (`verified: …; council-agreed: <ids>`); open-verification points count in the percentage's denominator and unexamined single-seat points block a percentage stop; rounds 2+ packets list every settled or frozen ID so a fresh seat does not raise it again, and a restated point is a duplicate, not a new ID; FINAL.md's ledger is updated at every verdict and rewritten before `resolved`.

v6 answered the Codex review of 2026-09-07: round-1 agreement needs the same fix, not just the same concern; the merge file is the cumulative ledger of every point; applies are reconciled by marker and document hash so an interrupted apply is never repeated; a new `FINAL REVIEW (resolved)` stage; every point ID ends applied / withdrawn / rejected / open; a single-seat policy and a no-concerns case; Setup writes LOG.md before pinning the agent files and saves each answer as it arrives; the seat agent files ship in the repo's `.claude/agents/`; `git add` precedes every pathspec commit; resume checks the document's identity.

v5 made any interrupt the pause: Esc / Ctrl+C / session end / a crash count as a pause, the typed word `pause` is only an answer at a prompt, the wait-or-cancel question is gone, and "Pausing on request" became "Stopping and pausing"; v5 also moved the debate files to `planning/packets/`, LOG.md to `planning/council_state/`, and the hand-off notes to `planning/status/`.
